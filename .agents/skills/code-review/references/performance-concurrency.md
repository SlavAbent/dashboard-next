# Code Review: производительность и конкурентность

## Что искать
- N+1 запросы к БД или API в цикле.
- Чтение всех строк, хотя нужен фильтр/пагинация.
- Блокирующие синхронные операции на Node.js event loop.
- Неограниченные `Promise.all` для тысяч задач.
- Запросы с отсутствующим индексом на горячем пути — оценивать по схеме и объёму.
- UI с дорогими вычислениями на каждом рендере (с указанием реального воздействия).
- Гонки между поисковыми запросами, мутациями и состоянием.
- Некорректная стратегия инвалидации кэша и показ устаревших данных.

## Пример: N+1
```ts
const posts = await prisma.post.findMany();
for (const post of posts) {
  post.author = await prisma.user.findUnique({ where: { id: post.authorId } });
}
```
Для N публикаций выполняется N дополнительных запросов. Используй подходящий `include`/`select`, join/batching в зависимости от схемы и версии ORM. Указывай влияние при ожидаемых объёмах.

## Пример: гонка запросов
```ts
async function search(query: string) {
  const result = await fetchResults(query);
  setResults(result);
}
```
Если запрос «a» завершится после «ab», старые результаты перезапишут новые. Возможные меры: отмена через `AbortController`, идентификатор последнего запроса, готовый query manager. Проверь, нет ли уже защиты выше по стеку.

## Приоритет
Фраза «может быть медленно» недостаточна. Покажи тип нагрузки, сложность/число запросов, конкретный путь выполнения и разумную альтернативу. Не навязывай мемоизацию до измерений.
