# Frontend-архитектура: React, Next.js и FSD

## Границы ответственности
- **app:** запуск, providers, маршрутизация и конфигурация.
- **pages:** сборка страниц, маршруты и page-level композиция.
- **widgets:** крупные самостоятельные части интерфейса.
- **features:** пользовательские действия и сценарии.
- **entities:** предметные сущности, их данные и представление.
- **shared:** общий UI и инфраструктура без доменного знания.

Учитывай фактическую версию и соглашения используемой методологии FSD. Не навязывай все слои проекту, которому достаточно меньшего числа.

## Пример дерева
```text
src/
  app/
  pages/
    tasks/
  widgets/
    task-board/
  features/
    create-task/
    update-task-status/
  entities/
    task/
      model/
      ui/
      api/
  shared/
    ui/
    lib/
```

`TaskBoard` композирует сущности и фичи; `shared/ui/Button` не должен импортировать `entities/task`.

## Зависимости
Высокоуровневая сборка использует нижележащие модули. Нарушение границ проявляется, например, когда `shared` импортирует конкретную feature. Сохраняй публичные API сегментов там, где это принято.

## State management
- Локальный UI state: `useState`.
- Глобальные клиентские взаимодействия: Zustand/Context при необходимости.
- Серверное состояние: TanStack Query или выбранная стратегия Next.js.
- Не дублируй кеш API в нескольких источниках без строгой синхронизации.

## Next.js
Разделяй Server и Client Components по фактической необходимости интерактивности. Серверная авторизация обязательна для защищённых операций. При выборе cache/revalidation учитывай версию Next.js, свежесть данных и границы доверия.

## Типичная ошибка
`shared/lib/tasks.ts` содержит статусы конкретных задач и импортирует `entities/task`. Это уже доменное знание, значит логика не относится к `shared`.
