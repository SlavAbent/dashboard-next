# Next.js: App Router и серверно-клиентские границы

## Версия важнее догадки

Сначала проверь `next`, `react`, конфигурацию и существующие соглашения. API кеширования, React Server Components и Server Actions зависят от версии.

## Server Components

Предпочитай серверные компоненты, если интерактивность не требуется.

```tsx
export default async function UsersPage() {
  const users = await getUsers();
  return <UsersList users={users} />;
}
```

`getUsers` здесь — существующая серверная функция, которая возвращает разрешённые для показа поля и выполняет требуемые проверки доступа.

## Client Components

Директива `'use client'` необходима для клиентских React Hooks, обработчиков событий и браузерных API.

```tsx
'use client';
import { useState } from 'react';

export function Counter() {
  const [count, setCount] = useState(0);
  return <button onClick={() => setCount(n => n + 1)}>{count}</button>;
}
```

Не делай всю страницу клиентской ради одной кнопки: выделяй интерактивный участок.

## Данные и API

- Учитывай, где именно выполняется запрос: сервер, клиент, Route Handler или Server Action.
- Выбирай стратегию актуализации данных по требованиям проекта, не предполагая автоматическое кеширование для любого `fetch`.
- Учитывай loading/error/empty-состояния.
- Не передавай серверные секреты в клиентские компоненты.
- Серверные операции обязаны самостоятельно проверять пользователя, его права и входные данные.
- Не вызывай собственный HTTP API с сервера без причины, если можно безопасно использовать серверный сервис напрямую.

## Route Handlers

Маршруты в `app/api/.../route.ts` выполняют HTTP-обязанности: парсинг, валидация, авторизация, вызов серверной логики, формирование ответа.

Не размещай объёмные бизнес-правила в обработчиках.

## Изменения и совместимость

- Сохраняй публичные URL и контракт ответа, если не требуется обратное.
- Учитывай динамические маршруты, streaming и обработку ошибок лишь когда они затронуты задачей.
- Проверяй документированное поведение конкретной версии Next.js перед изменением кеширования и revalidation.
