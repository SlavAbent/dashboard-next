# Repository Guidelines

## Scope & Specialized Guides

Эти общие правила действуют во всем репозитории. 
При работе над бэкендом также следуйте указаниям из `backend/AGENTS.md` (включая рекомендации для серверного кода, расположенного вне директории `backend/`). При работе над фронтендом следуйте указаниям из `frontend/AGENTS.md` (включая рекомендации для UI-пакетов, расположенных вне директории `frontend/`). 
Если изменения затрагивают обе части, необходимо руководствоваться обоими документами.

## Project Organization

- `frontend/`: приложение на Next.js 15, TailwindCSS, Zustand, shadCN/ui, Tanstack Query, ZOD, YUP, @dnd-kit/react.
- `backend/`: собственный сервер на Nodejs/Express5, проверка данных для базы, а также данные для JSON Server.
- `packages/*/src/`: переиспользуемые модули: часы, «Помодоро», погода и чат.
- `prisma/`: модели базы данных и миграции; `lib/`: вспомогательные утилиты приложения.
- `tests/`: папка для тестов, на данный момент пустые.

Пакеты предоставляют публичные точки входа вида `@dashboard/*`; 
импорт из директории `frontend/` или корневой папки `lib/` запрещены

## Setup & Shared Commands

Используй Node.js версии 24 или выше. Выполняй команды из корневого каталога репозитория. 
Установи зависимости с помощью `pnpm install` и настройте файл `.env.local» в соответствии с инструкциями в `README.md`.

- `npm run dev`: запуск PostgreSQL, проверка соединения, а также запуск пользовательского сервера (Next.js/Socket.IO) и JSON Server.
- `npm run check`: выполнение проверок с помощью Prettier, ESLint и TypeScript.
- `npm run lint:fix` / `npm run format`: автоматическое исправление ошибок линтинга или форматирование файлов.
- `colima start` / `colima stop`: выполняй для запуска утилиты colima и Docker-контейнеров (без него проект не запустится в текущем виде)

## Shared Coding Style

Для написания типизированного кода используйте строгий режим TypeScript. 
Prettier обеспечивает использование отступов в два пробела, одинарных кавычек, точек с запятой и ограничение длины строки в 80 символов. 
ESLint следит за тем, чтобы импорты были отсортированы. Придерживайтесь существующих соглашений об именовании; публичные API предоставляйте через `index.ts` (там, где это принято).
