# Code Review: Backend, Prisma и безопасность

## Проверки
- Авторизация для каждой операции с ресурсами и проверка принадлежности ресурса.
- Валидируются ли body, params, query, в том числе диапазоны и типы?
- Нет ли SQL injection в raw SQL, command injection, SSRF, утечки секретов?
- Пароли хешируются, токены не выводятся в логи, секреты остаются на сервере.
- Корректно ли обрабатываются ошибки Express согласно версии и используемому middleware?
- Может ли запрос создать частичную запись при падении второй операции?
- Есть ли ограничения БД (unique, foreign keys), которые поддерживают инварианты?
- Возвращаются ли только разрешённые поля, без passwordHash и внутренней информации?

## Пример: отсутствие проверки владельца
```ts
app.delete('/tasks/:id', requireAuth, async (req, res) => {
  await prisma.task.delete({ where: { id: req.params.id } });
  res.sendStatus(204);
});
```
Аутентифицированный пользователь может удалить чужую задачу, если знает её ID. Право доступа необходимо проверять на сервере с привязкой ресурса к пользователю; вариант решения зависит от модели и допустимой семантики ответа.

## Пример: частичная операция
```ts
await prisma.account.update({ /* списание */ });
await prisma.payment.create({ /* запись */ });
```
Если вторая операция упадёт, списание уже выполнено. При связанном инварианте нужна транзакция. В финансовой логике также проверяй конкурентные списания и инварианты баланса.

## Достаточность доказательства
Не считай endpoint уязвимым только потому, что в его функции не видно middleware. Проследи глобальные guard'ы, route-level hooks, политики доступа и фактическую архитектуру. Указывай только то, что действительно подтверждено.
