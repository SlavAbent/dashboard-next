# Testing — проверка поведения системы

**Цель:** писать воспроизводимые тесты, которые выявляют реальные регрессии, а не проверяют детали реализации.

## Процесс
1. Изучи `AGENTS.md`, существующие тесты, `package.json`, конфигурацию runner'а, фикстуры и окружение. Не меняй Jest на Vitest (или наоборот) без запроса.
2. Определи требования и границу тестирования: unit / integration / component / E2E; выбери минимально достаточный уровень.
3. Прочитай **[references/fundamentals.md](references/fundamentals.md)** и только необходимые тематические референсы.
4. Составь сценарии: успех, ошибка, крайние значения, права и конкурентность (где релевантно).
5. Напиши тесты, запусти относящиеся к ним команды, исправь реальные ошибки, повтори запуск.
6. Не ослабляй assertions и не меняй production-код только ради зелёного результата. Если обнаружен дефект продукта, сообщи, а исправляй только в согласованном объёме задачи.

## Цикл тестирования

1. Начинай этап только после `REVIEW_APPROVED` для текущего diff.
2. Запусти минимально достаточный набор проверок и зафиксируй точную команду, окружение и результат.
3. Классифицируй каждое падение:
   - дефект продукта — верни `TESTS_PRODUCT_DEFECT` с воспроизведением, ожидаемым и фактическим результатом;
   - дефект теста или фикстуры — исправь тест в разрешённом scope и повтори проверку;
   - проблема окружения — выполни безопасную диагностику и верни `TESTS_BLOCKED`, если устранение требует нового разрешения или внешнего изменения.
4. После исправления production-кода не продолжай со старого результата: дождись повторного code review и перезапусти затронутые проверки.
5. Если одна и та же причина падения повторилась три раза, останови попытки и верни доказательства блокера главному агенту.
6. Когда все обязательные проверки прошли, верни `TESTS_PASSED` с покрытыми сценариями и списком не запускавшихся проверок.

Успешный build, статическая проверка или Storybook-сценарий не заменяют требуемую проверку фактического пользовательского поведения.

## Отчёт
- **Что покрыто** — сценарии и уровни тестов.
- **Файлы** — созданные/изменённые тесты.
- **Выполненные команды** — фактические результаты, без домыслов.
- **Ограничения** — не запущенные тесты, недоступная БД, известные проблемы, пробелы.

Соблюдай принятые в репозитории пути/паттерны именования. Не устанавливай новые библиотеки без разрешения. Примеры в референсах адаптируй к установленным версиям.
