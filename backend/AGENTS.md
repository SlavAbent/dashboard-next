# Backend Guidelines

## Scope & Organization

Данные правила распространяются на директорию `backend/`, а также на любые серверные компоненты в других частях проекта: модели и миграции Prisma, утилиты для работы с базой данных (например, `lib/prisma.ts`), код аутентификации, API-маршруты в `frontend/app/api/` и серверные модули, такие как `packages/chat/src/server.ts`. Также следуйте указаниям из корневого файла `AGENTS.md`.

- `backend/server.js`: пользовательский HTTP-сервер на базе Next.js и обработчики Socket.IO.
- `backend/app.ts`: приложение Express с эндпоинтом для проверки работоспособности (health check).
- `backend/scripts/validate-db.mjs`: проверка соединения с базой данных.
- `backend/db/`: данные для JSON Server и примеры фикстур (начальных наборов данных).
- `prisma/`: модели базы данных и версионируемые миграции.

Не включайте зависимости, предназначенные только для серверной части, в точки входа пакетов, используемых на клиенте. Соблюдайте границы пакетов и используйте публичные API для взаимодействия между модулями.

## Development & Database Commands

Выполняйте команды из корневой директории репозитория:

- `npm run backend`: запуск пользовательского сервера (Next.js/Socket.IO); по умолчанию используется порт 3000.
- `npm run json-server`: запуск JSON Server для файла `backend/db/db.json` на порту 4001.
- `npm run db:start` / `npm run db:stop`: запуск или остановка PostgreSQL с помощью Docker Compose.
- `npm run validate:db`: проверка соединения с базой данных.
- `npm run db:logs` / `npm run db:studio`: просмотр логов PostgreSQL или содержимого базы данных.
- `npm start`: запуск пользовательского сервера в продакшн-режиме (после выполнения `npm run build`); PostgreSQL и JSON Server должны быть запущены отдельно.

Перед реализацией кода строго задай мне ряд критически важных вопросов для реализации кода и/или дай наводку как лучше сделать и предложи это - если я дам согласие и/или если я отвечу на твои вопросы, то выполни команду `/plan` и составь todo-list по релазиации текущей задачи. Как это все сделаешь, оповести меня, что готов начать работу.

Как только выполнишь задачу, то выполни все тесты, проверь на ошибки свой код и убедись что все работает. Если проблемы будут найдены - исправь их

## Implementation & Configuration

Придерживайтесь существующих соглашений об использовании ES-модулей и применяйте строгий режим TypeScript для обеспечения типизации. Проверяйте входящие данные в запросах и событиях сокетов, выполняйте проверку аутентификации перед совершением защищенных действий, а также убедитесь в успешности операций сохранения данных, прежде чем подтверждать выполнение запроса. Храните учетные данные в локальном конфигурационном файле (переменные окружения); список необходимых переменных можно найти в `README.md`.
