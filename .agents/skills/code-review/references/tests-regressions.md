# Code Review: тесты и регрессии

## Проверяй
- Появились ли новые ветки поведения без критически нужных проверок?
- Покрывают ли тесты негативные сценарии, права доступа, 404/500, отмену, дубли?
- Не стали ли тесты проверять только моки вместо поведения?
- Не отключены ли падающие тесты (`skip`, `only`, искусственные утверждения)?
- Не изменены ли ожидания только ради зелёного CI?
- Используется ли детерминированная тестовая среда, независимы ли тесты?

## Пример недостаточного теста
```ts
test('удаление', async () => {
  await deleteTask('1');
  expect(true).toBe(true);
});
```
Тест не проверяет результат удаления. Лучше проверить вызов разрешённой зависимости или состояние системы/API; выбирать подходящий уровень тестирования.

## Правила оценки
Отсутствие теста само по себе не P1. Соотнеси отсутствие проверки с риском изменения. Для исправления проверки прав, например, важен сценарий «пользователь A не удаляет объект пользователя B».

## Что запускать
Запускай доступные целевые тесты и инструменты, если это уместно и безопасно. Не изменяй код при read-only ревью. Указывай точные команды и результаты; тесты, которые не запускались, перечисляй как ограничение.
