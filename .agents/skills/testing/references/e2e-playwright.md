# E2E-тесты: Playwright

## Назначение
Проверять ключевые пользовательские потоки с браузером, реальными маршрутами и рабочим приложением. E2E медленнее unit-тестов, поэтому покрывай приоритетные сценарии, а не каждую мелкую ветку.

## Пример
```ts
import { test, expect } from '@playwright/test';

test('пользователь может открыть страницу задач', async ({ page }) => {
  await page.goto('/tasks');
  await expect(page.getByRole('heading', { name: 'Задачи' })).toBeVisible();
});
```
Для этого примера должны быть настроены `baseURL`, доступный сервер и тестовые данные/учётная запись (если есть авторизация).

## Правила
- Используй `getByRole`, `getByLabel`, `getByTestId` только при необходимости.
- Не используй `waitForTimeout(3000)` вместо ожидания состояния.
- Тесты изолированы: создавай и очищай тестовые данные безопасно.
- Не используй общую изменяемую учётную запись в параллельных сценариях без контроля.
- При сбое сохраняй trace/screenshot согласно настройкам проекта.
- Проверяй не только навигацию, но и наблюдаемый результат (изменённая задача, сообщение, список).

## Пример плохой синхронизации
```ts
await page.waitForTimeout(2000);
await page.getByText('Сохранено').click();
```
Время загрузки не гарантировано. Жди конкретный элемент/состояние и взаимодействуй с ним.

## Сценарии
- Логин и доступ к защищённой странице.
- Создание/изменение/удаление объекта.
- Ошибка серверного запроса.
- Пользователь без прав не видит/не выполняет запрещённую операцию (проверь также API-тестом).

## Отчёт
Укажи браузеры, фактически выполненные сценарии, причину flaky-сбоев и артефакты, если доступны. Никогда не заявляй об успехе E2E без запуска приложения.
