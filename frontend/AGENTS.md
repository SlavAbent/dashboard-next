# Frontend Guidelines

## Scope & Organization

Данные правила распространяются на код пользовательского интерфейса (UI) во фронтенде, а также на UI-компоненты в директориях `packages/*/src/`. Также следуйте указаниям из корневого файла `AGENTS.md`. Вопросы, касающиеся аутентификации, API-маршрутов или доступа к данным на стороне сервера, регулируются файлом `backend/AGENTS.md`.

Используйте архитектурный подход Feature-Sliced ​​Design (FSD), описанный в `frontend/FSD.md`:

- `app/`: маршруты (routes), макеты (layouts) и провайдеры Next.js.
- `widgets/`: композиции страниц.
- `features/`: пользовательские взаимодействия и рабочие процессы.
- `entities/`: доменные модели, состояние (state) и доступ к данным.
- `shared/`: переиспользуемые компоненты, хуки, иконки и утилиты для работы с API.

Слои могут импортировать сущности только из нижележащих слоев. Избегай импортов между виджетами. 
Импортируй слайсы (slices) через публичные API (если они предусмотрены). Иконки размещай в `shared/icons/`, 
а переиспользуемые компоненты — строго в `shared/components/`

## Workspace Packages

Реализации часов, таймера «Помодоро», виджета погоды и чата находятся в корневой директории `packages/*/src/`. 
Используй их через публичные точки входа `@dashboard/*`. Пакеты не должны импортировать код из `frontend/` 
или корневой папки `lib/`; передавай зависимости через публичные API или объявляйте их в манифесте пакета.

## Development & Build Commands

Run commands from the repository root:

- `npm run dev`: запуск среды разработки (доступна по адресу `http://localhost:3000`).
- `npm run build`: создание production-сборки Next.js из директории `frontend/`.
- `npm run check`: проверка форматирования, правил линтинга и типов TypeScript.

Перед реализацией кода строго задай мне ряд критически важных вопросов для реализации кода и/или дай наводку как лучше сделать и предложи это - если я дам согласие и/или если я отвечу на твои вопросы, то выполни команду `/plan` и составь todo-list по релазиации текущей задачи. Как это все сделаешь, оповести меня, что готов начать работу.

Как только выполнишь задачу, то выполни все тесты, проверь на ошибки свой код и убедись что все работает. Если проблемы будут найдены - исправь их

## UI Coding Style

Используйте PascalCase для названий React-компонентов, а имена хуков начинайте с префикса `use`. Придерживайтесь стиля именования файлов (camelCase) и существующих соглашений, например: `*.types.ts`, `*.store.ts`, а также файлы типов должны лежать в той же директории, что и код, который они описывают. Соблюдайте правила линтинга для React Hooks и TanStack Query. Для сортировки классов Tailwind CSS используйте плагин Prettier; применяйте готовые общие компоненты и существующие соглашения по оформлению (темизации).
