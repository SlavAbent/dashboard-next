# Безопасность и производительность

## Когда читать

Обязательно при работе с аутентификацией, авторизацией, публичными API, пользовательскими данными, секретами, файлами, платежами и высоконагруженными участками.

## Безопасность

- Валидируй все внешние данные: `body`, `params`, `query`, cookies, ответы внешних API.
- Авторизация должна выполняться на сервере, даже если UI скрывает запрещённое действие.
- Проверяй доступ к **конкретному ресурсу**, а не только факт входа пользователя.
- Не логируй пароли, токены, cookies, ключи и другие секреты.
- Не возвращай `passwordHash` и внутренние поля через API.
- Не раскрывай детали SQL/Prisma/stack traces клиенту.
- Используй параметризованные запросы; избегай небезопасной сборки SQL из строк.
- Учитывай CSRF, XSS, rate limiting, CORS и проверки файлов в контексте конкретного сценария.
- Учитывай Top 10 OWASP 2025.

### Пример опасной авторизации

```ts
app.delete('/users/:id', async (req, res) => {
  await prisma.user.delete({ where: { id: req.params.id } });
  res.sendStatus(204);
});
```

Проблема: пользователь может попытаться удалить чужой ресурс. Перед удалением необходимо проверить аутентификацию, полномочия на этот `id` и валидность параметра.

## HTTP-ошибки

`fetch` не выбрасывает исключение для HTTP 4xx/5xx.

```ts
async function getTasks(): Promise<unknown> {
  const response = await fetch('/api/tasks');
  if (!response.ok) throw new Error(`HTTP ${response.status}`);
  return response.json();
}
```

После получения JSON выполни runtime-валидацию перед использованием. Обрабатывай ошибки на подходящей границе приложения.

## Производительность Frontend

- Сначала установи источник лишней работы, затем оптимизируй.
- Не добавляй мемоизацию без причины.
- Учитывай размер бандла, lazy loading, тяжёлые вычисления и размер списков.
- Уменьшай лишние запросы, но не нарушай актуальность данных.

## Производительность Backend и БД

- Избегай N+1-запросов.
- Используй пагинацию для потенциально больших выборок.
- Оцени индексы по реальным запросам и профилю нагрузки.
- Не блокируй event loop длительной синхронной работой.
- Ограничивай обращения к удалённым системам таймаутами, когда это необходимо.

## Отчётность

Не называй изменение «ускорением» без измерений или явного технического основания. Фиксируй, что было измерено и при каких условиях.
