# Backend: Express, API и слои ответственности

## Разделение слоёв

- **Route:** связывает HTTP-метод и обработчик.
- **Controller:** читает/валидирует HTTP-вход, инициирует операцию, возвращает статус и DTO.
- **Service:** реализует бизнес-правила и сценарий использования.
- **Repository:** реализует доступ к данным.

Не требуй механически всех четырёх слоёв для любого маленького модуля. Соблюдай границы, уже действующие в проекте.

### Условный пример

```ts
// route
router.get('/users', userController.getAll);

// controller (ошибки обрабатываются middleware/соглашениями проекта)
async function getAll(req: Request, res: Response) {
  const users = await userService.getAll();
  res.status(200).json(users);
}

// service
async function getAll() {
  return userRepository.findPublicUsers();
}

// repository
async function findPublicUsers() {
  return prisma.user.findMany({
    select: { id: true, name: true }
  });
}
```

Это схематический пример: типы контроллера и обработка ошибок зависят от Express-версии и конфигурации проекта.

## Валидация и ошибки

- Валидируй `params`, `query`, `body`; TypeScript не проверяет runtime-ввод.
- Корректно различай ошибки клиента, отсутствие ресурса, конфликт и внутреннюю ошибку.
- Не отдавай stack traces, приватные данные и внутренние сообщения клиенту.
- Не оставляй unhandled promise rejections.
- Для Express учитывай версию и принятую стратегию async error handling.

## Асинхронность

- Независимые операции при необходимости запускай параллельно.
- `Promise.all` подходит, если ошибка любой операции делает общий результат ошибочным.
- `Promise.allSettled` подходит, если нужно отдельно обработать каждый исход.
- Учитывай таймауты, отмену, повторные запросы и идемпотентность, когда этого требует сценарий.

## REST-контракты

- Соблюдай согласованные URL, HTTP-методы, статусы и формат ошибок.
- На сервере проверяй авторизацию для каждого защищённого действия.
- Разделяй DTO и модели хранения при наличии приватных полей.
- Не ломай обратную совместимость без анализа потребителей.

## Безопасность
